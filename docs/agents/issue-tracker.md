# Requirements and issue tracking

The current repository remote identifies the issue tracker. Use `git remote -v`
and read existing issues before assuming the organization transfer has happened.
The user's request is sufficient for ordinary work; creating an issue is not a
prerequisite and posting one requires authorization.

For a review, identify an issue, supplied spec, or explicit user request. Record
the exact base commit. Review both committed and requested working-tree changes.
The standards source is CONTRIBUTING.md and applicable nested instructions. Keep
standards findings separate from requirements findings.

The initial improvement requirements and remaining acceptance work are captured
in [the roadmap](../roadmap.md); source-backed comparisons live in
docs/research.
