# VPN integration and security choices

nix-homelab imports the locked `nix-forge/vpn-confinement` module and configures
its public options. It does not patch that dependency, replace its modules or
install a second namespace firewall. `modules/vpn/wireguard.nix` is this
project's adapter, despite its similar name. Input `follows` declarations share
the chosen nixpkgs and flake-parts inputs; they do not edit upstream source.
Sharing nixpkgs does change the dependency's evaluation environment, which is
why consumer tests remain necessary.

## What the defaults permit

| Choice                                                 | Effect and tradeoff                                                                                                                                                                                                                                                                                                                                |
| ------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `balanced` namespace with `servicePolicy = "enforced"` | Dynamic tunnel destinations remain possible, while upstream requires empty service capability sets and rejects privileged or unverified lifecycle commands, unconfined activation or inherited sockets, root execution, disabled NoNewPrivileges and service exception flags. This does not claim the destination restrictions of `highAssurance`. |
| `allowAllTunnel` egress                                | Allows arbitrary destinations through WireGuard for dynamically discovered torrent peers. It does not allow arbitrary host-link or cleartext egress. A destination allowlist is stronger but does not fit a general torrent client.                                                                                                                |
| Strict DNS and endpoint pinning                        | Keep resolver traffic in the tunnel and restrict WireGuard's transport endpoint. Host resolver IPC, hostname endpoints and insecure key material remain disabled.                                                                                                                                                                                  |
| Published web ports                                    | Let trusted host processes reach selected namespace ports. This expands access compared with no host link. Application authentication remains necessary; publication does not open the LAN firewall.                                                                                                                                               |
| Shared namespace                                       | Confined applications share a network trust domain. Use separate upstream namespaces for applications that must not communicate with each other.                                                                                                                                                                                                   |
| Media `UMask = "0007"`                                 | Allows group-write permission compared with the VPN baseline's `0027`, so distinct download and library-manager users can manage shared files when the application creates them group-writable. Other users receive no access through this mask. Players use `0077` for private file creation and retain read-only library mounts.                 |
| Application writable directories                       | Permit required state and media writes within filesystem sandboxes. They do not change network confinement.                                                                                                                                                                                                                                        |

The enforced policy rejects `allowUnsafeCapabilities`,
`allowPrivilegedCommands`, `allowHostSockets` or `allowRootInHighAssurance` when
enabled. The policy check verifies these flags and the effective empty
capability sets, rather than inferring safety from a profile's name. Upstream's
baseline application hardening remains in use for downloaders; Tinyproxy selects
its strict application profile. Namespace profiles and application hardening
profiles are separate settings.

## Understanding command warnings

Upstream accepts plain commands and a conservative subset of quoted absolute
executable paths, including harmless trailing whitespace generated by native
NixOS modules. Privileged prefixes and ambiguous executable syntax remain
rejected under the enforced service policy. No exception is needed for ordinary
qBittorrent command quoting. The checker does not inspect executable contents
and is not a complete systemd command parser.

## Which settings belong upstream

Strict DNS and `allowAllTunnel` already match upstream defaults. Homelab
requires strict DNS, but inherits egress policy from the namespace profile. A
host can select `highAssurance` and supply `egress.allowedCidrs` without forcing
an override of homelab's egress setting. Default torrent deployments still use
`balanced` with dynamic destinations inside the tunnel. Endpoint pinning
strengthens the upstream default. Provider addresses, DNS servers and selected
published ports describe this deployment and cannot be chosen by a generic
module.

Service validation belongs upstream. Homelab selects
`servicePolicy = "enforced"` instead of duplicating privilege checks or
disabling them to accommodate dynamic peers. The enforced policy rejects service
exceptions independently of the namespace profile. Upstream also fixes
`highAssurance` validation of known root identities and omitted
capability-bounding directives. Existing explicit profile-mode exceptions remain
available; configurations that accidentally relied on those validation gaps must
be corrected.

Filesystem permissions belong to the application integration. Homelab uses
stronger `ProtectHome` and `ProtectSystem` defaults at priority 950, between
upstream baseline defaults at 1000 and its strict profile at 900. This avoids
conflicting defaults without weakening upstream's strict profile or forcing
applications away from explicit native sandbox settings. Lowering the priority
of all upstream security settings would hide conflicts with weaker consumer
settings and is not the solution.

Group-write creation remains necessary for downloaders and library managers.
Players do not need it. Their private-file mask is `0077`; shared media access
comes from the supplementary group and their library mounts remain read-only.

## Where improvements belong

- **vpn-confinement:** namespace/firewall enforcement, DNS containment,
  WireGuard lifecycle, privilege validation, diagnostics and generic security
  profiles. Improve ambiguous warnings there so every consumer benefits.
- **nix-homelab:** application selection and attachment, UI ports, credentials,
  media permissions, application sandbox compatibility and integration tests. Do
  not copy or weaken upstream enforcement to make an application start.
- **Consuming host:** Mullvad values, nix-seal catalog, physical mounts, access
  policy and backup destinations.

The `configuration-vpn-policy` check evaluates the effective policy for
qBittorrent, both optional Usenet clients and the indexer proxy. The VPN VM
checks real tunnel traffic, DNS, host/LAN access, tunnel failure and recovery.
The media VM checks application startup, permissions and credential rotation.
These checks establish specific behavior, not an independent security audit.
